After logging in, doctors see a dedicated dashboard:

- **Active Patient Chats:** Real-time list of patients waiting for consultation
- **Urgency Indicators:**

Real-time messaging system between patients and doctors:

**For Patients:**

- Send text messages
- See doctor's name and specialty

**For Doctors:**
- Accept chat requests from patients
- View full conversation history
- Send professional medical advice
- Multiple concurrent patient chats

**Features:**
- Message persistence
- Timestamp display
- Read receipts
- Session-based organization
- Chief complaint visible at top

### 4. **Enhanced Authentication** 🔐

**Dual Login System:**
- **Patient Login:** Original flow unchanged

  - Toggle on login screen: "👨‍⚕️ Login as Doctor"

**Security Features:**
- User type verification (prevents patients logging in as doctors)
- Separate JWT claims for doctors
- Online/offline status tracking

### Backend (server.js) Changes

**New Endpoints:**

1. **POST** `/api/auth/register-doctor`
   - Registers new doctor
   - Creates user account with `user_type='doctor'`
   - Creates doctor profile in `doctors` table
   - Returns JWT with `doctor_id`

2. **POST** `/api/auth/logout`
   - Marks doctor as offline
   - Invalidates session

3. **GET** `/api/doctors/online`
   - Returns list of online doctors
   - Sorted by rating and experience

4. **POST** `/api/chat-sessions`
   - Creates new patient-doctor chat session
   - Assigns to specific doctor or finds available one

5. **GET** `/api/chat-sessions`
   - Returns active sessions for patient or doctor
   - Different query for each user type

6. **GET** `/api/chat-sessions/:id/messages`
   - Retrieves all messages in a conversation
   - Returns formatted DirectMessage objects

7. **POST** `/api/chat-sessions/:id/messages`
   - Sends new message
   - Updates last_message_at timestamp
   - Returns formatted message with sender name

8. **PUT** `/api/chat-sessions/:id/read`
   - Marks all messages as read
   - Updates is_read flag

**Updated Endpoints:**
- `POST /api/auth/login` - Now supports `user_type` parameter
- `POST /api/auth/register` - Sets `user_type='patient'` by default

### Database Schema Updates

**Updated `users` Table:**
```sql
ALTER TABLE users ADD COLUMN user_type VARCHAR(20) DEFAULT 'patient';
```

**Updated `doctors` Table:**
```sql
ALTER TABLE doctors ADD COLUMN hospital VARCHAR(200);
ALTER TABLE doctors ADD COLUMN license_number VARCHAR(100);
ALTER TABLE doctors ADD COLUMN user_id INT REFERENCES users(id);
```

**New `chat_sessions` Table:**
```sql
CREATE TABLE chat_sessions (
  id                SERIAL PRIMARY KEY,
  patient_id        INT REFERENCES users(id),
  doctor_id         INT REFERENCES doctors(id),
  chief_complaint   TEXT NOT NULL,
  urgency           VARCHAR(20) DEFAULT 'MODERATE',
  status            VARCHAR(20) DEFAULT 'waiting',
  created_at        TIMESTAMPTZ DEFAULT NOW(),
  last_message_at   TIMESTAMPTZ
);
```

**New `direct_messages` Table:**
```sql
CREATE TABLE direct_messages (
  id            SERIAL PRIMARY KEY,
  session_id    INT REFERENCES chat_sessions(id),
  sender_id     INT REFERENCES users(id),
  sender_type   VARCHAR(20) NOT NULL,
  message       TEXT NOT NULL,
  is_read       BOOLEAN DEFAULT FALSE,
  created_at    TIMESTAMPTZ DEFAULT NOW()
);
```

## 📝 HOW TO USE

### For Doctors:

1. **Registration:**
   - Open HealthBridge app
   - Tap "Sign Up" → "Register as Doctor"
   - Fill in all professional credentials
   - Specialty, Hospital, License Number required
   - Create secure password
   - Tap "Register as Doctor"

2. **Login:**
   - Open app → Login screen
   - Tap "👨‍⚕️ Login as Doctor" toggle
   - Enter email and password
   - Tap "Login as Doctor"
   - You'll be taken to Doctor Dashboard

3. **Managing Chats:**
   - See list of patients requesting consultation
   - Urgency levels shown with colored indicators
   - Tap on a patient to open chat
   - Send professional medical advice
   - Chat history is preserved

4. **Logout:**
   - Tap logout icon in top-right corner
   - Confirms you want to go offline
   - Marks you as unavailable to new patients

### For Patients:

1. **Connecting to Doctor:**
   - Use AI Chat to describe symptoms
   - AI will assess severity
   - If needed, AI says "Let me connect you to an online doctor"
   - You'll be routed to a real doctor
   - Start live chat immediately

2. **Chatting with Doctor:**
   - Send messages describing symptoms
   - Doctor responds with medical advice
   - Full conversation history visible
   - Chief complaint shown at top

## 📊 DATABASE MIGRATION REQUIRED

**IMPORTANT:** Before testing, run this SQL in your Supabase SQL Editor:

```sql
-- Add user_type column to users
ALTER TABLE users ADD COLUMN IF NOT EXISTS user_type VARCHAR(20) DEFAULT 'patient';

-- Add doctor columns
ALTER TABLE doctors ADD COLUMN IF NOT EXISTS hospital VARCHAR(200);
ALTER TABLE doctors ADD COLUMN IF NOT EXISTS license_number VARCHAR(100);
ALTER TABLE doctors ADD COLUMN IF NOT EXISTS user_id INT REFERENCES users(id) ON DELETE SET NULL;

-- Create chat_sessions table
CREATE TABLE IF NOT EXISTS chat_sessions (
  id                SERIAL PRIMARY KEY,
  patient_id        INT REFERENCES users(id) ON DELETE CASCADE,
  doctor_id         INT REFERENCES doctors(id) ON DELETE SET NULL,
  chief_complaint   TEXT NOT NULL,
  urgency           VARCHAR(20) DEFAULT 'MODERATE',
  status            VARCHAR(20) DEFAULT 'waiting',
  created_at        TIMESTAMPTZ DEFAULT NOW(),
  last_message_at   TIMESTAMPTZ
);

-- Create direct_messages table
CREATE TABLE IF NOT EXISTS direct_messages (
  id            SERIAL PRIMARY KEY,
  session_id    INT REFERENCES chat_sessions(id) ON DELETE CASCADE,
  sender_id     INT REFERENCES users(id) ON DELETE CASCADE,
  sender_type   VARCHAR(20) NOT NULL,
  message       TEXT NOT NULL,
  is_read       BOOLEAN DEFAULT FALSE,
  created_at    TIMESTAMPTZ DEFAULT NOW()
);

-- Create indexes for performance
CREATE INDEX IF NOT EXISTS idx_chat_sessions_patient ON chat_sessions(patient_id);
CREATE INDEX IF NOT EXISTS idx_chat_sessions_doctor ON chat_sessions(doctor_id);
CREATE INDEX IF NOT EXISTS idx_direct_messages_session ON direct_messages(session_id);
CREATE INDEX IF NOT EXISTS idx_doctors_user_id ON doctors(user_id);
CREATE INDEX IF NOT EXISTS idx_doctors_online ON doctors(is_online);
```
